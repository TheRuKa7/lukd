Updated 7 November 2026. DECISIONS D01/D02/D08 apply. A designed book describes work; it does not prove runtime art exists.

## 1. Purpose and evidence

Markdown is canonical; PDFs are derivative reference artifacts. `tools/canon.py` indexes selected facts and must fail when required fields disappear. No verified study of another publisher's book is claimed. Current style is specified in ART_DIRECTION.

Use **specified**, **implemented**, **verified**, **not in scope**. Concepts, vector figures and base rasters are references, not accepted rigs. The 6 November PDFs remain historical until rebuilt; retain the new input manifest. No source Blender scenes, layered character packs or accepted audio were present at baseline.

## 3. Asset contract

Record ID/version; scope; owner agent; story use/canon locks; reference hashes; camera/floor/pivots; palette; source/runtime sizes; layers/states; exact counts/handedness; exclusions; validator and test-scene evidence. Also record provider/model/request if applicable, source script/scene, rights evidence, cost if known and actual processing. Mark unsupported seeds/versions unavailable rather than inventing them.

Meaningful writing, Civic/Audit Omens, resonance and `NaN` remain runtime/code-native labels. Empty plates exclude actors/UI; moving parts need hidden surfaces. Preserve scripts/scenes so a correction repeats.

## 4. Strictly AI, free-first pipeline

| Step | Output | Default route |
|---|---|---|
| Research | Dated source/claim/uncertainty notes | Primary sources; no copying/authenticity claim |
| Layout | Reproducible scene/vector | AI-authored Blender Python/SVG |
| Candidate | Game-size actor/enemy/reel frame | Procedural render; optional existing generation access |
| Correction | Specific changed source/asset | AI-directed edit/script/re-render/rejection; no mandatory manual overpaint |
| Motion | Anticipation/contact/recovery, hurt/victory | Scripted poses/rig; no video-derived gameplay dependency |
| Integration | Imported asset in Unity test scene | Runtime dimensions, pivots, alpha, layers and budget |
| Acceptance | Captured sequence/checks/provenance | Reviewer agent + player readability evidence |
| Presentation | Source-linked offline HTML/PDF | Python builders + local Chromium |

Meshy's [rigging API](https://docs.meshy.ai/en/api/rigging) targets textured humanoids with clear limbs; it does not promise umbrella/tail/robe/facial rigs. [Remesh](https://docs.meshy.ai/en/api/remesh) provides target topology/count, not guaranteed deformation-ready geometry. Inspect/pose-test optional generated bases in Blender. Preserve originals/exports.

Higgsfield's [API quick start](https://open.higgsfield.ai/quick-start) documents asynchronous jobs; read current model/connector schemas. Current connector exposes reference Elements; only completed compatible elements are usable. References improve consistency without certifying it. Save/reconcile job IDs; do not duplicate uncertain charged requests. Shipped gameplay has no runtime generation service.

## 6. Book structure and reproducibility

Keep a designed cover, scope/status page, eras, regional scripts, labelled candidate plates, selected sheets, symbols/charms and production priorities. Future regions stay visibly future. No painting-per-district quota before the jam.

Builders support `--check`(no output), `--html-only`, `--output-dir PATH`; defaults retain README PDF filenames. For previews use `--html-only --output-dir build/review-artbook`. Dependencies: Python Pillow; Markdown additionally for bible; Node Playwright with installed Chromium; ffmpeg only for bible motion stills. Renderer blocks remote requests. No network font download. Input manifests record hashes; image/video caches key source bytes plus parameters.

After a PDF rebuild inspect overflow-prone pages and representative spreads for clipping, missing glyphs, broken images and incorrect facts. Rendering alone is not visual acceptance. Root integration owns final regenerated books and verification.
